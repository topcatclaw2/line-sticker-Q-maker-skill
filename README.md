# LINE 寫實 Q 版貼圖製作 Skill

這是一個用於製作 LINE 貼圖的 Codex Skill。它會依據使用者上傳的主角參考圖片與貼圖主題，將主角轉換為「臉部寫實、身體卡通」的 Q 版娃娃，製作 8 款風格一致、文字為繁體中文的 LINE 貼圖。

本 Skill 的核心設計是分階段確認：先確認 8 款貼圖文字，再產生總圖；確認最新總圖後，才進行切割與淺灰背景去背。這可以避免在文字或角色設計尚未確定時，提前產生大量不易修改的成品。

## 功能

- 以使用者上傳圖片中的主角作為角色參考，保留臉部特徵、髮型及辨識度高的特色。
- 將角色轉換為臉部寫實、身體卡通的 Q 版娃娃。
- 依照使用者提供的主題產生 8 款貼圖文字與動作構想。
- 使用使用者指定的詞句與標點；指定詞句不足 8 句時補足建議，超過 8 句時請使用者選擇。
- 產生一張橫向 16:9、4 欄 × 2 列的 8 款貼圖總圖。
- 讓姿勢與文字排版有變化，例如站立、坐姿、跳躍、探頭、弧形文字、斜向文字或對話框排版。
- 統一使用淺灰背景、文字與圖案白框，以及每格的裁切安全留白。
- 在確認總圖後，依照實際空白區切割成 8 張，再逐張移除淺灰背景並輸出透明 PNG。
- 交付總圖、裁切圖、透明 PNG、預覽圖、提示詞、製作 brief 及 ZIP 封裝檔。

## 使用方式

在 Codex 中明確指定這個 Skill，並提供主角圖片與主題。例如：

```text
使用 $line-sticker-maker，根據我上傳的照片製作「上班日常」LINE 貼圖。
請先提出 8 款繁體中文文字供我確認，再開始產圖。
指定詞句：
1. 早安，開工啦！
2. 收到！
3. 馬上處理
```

也可以只提供主題，讓 Skill 先提出 8 款建議文字：

```text
使用 $line-sticker-maker，主題是「貓咪的週末生活」。
請先給我 8 款繁體中文貼圖文字與每款的姿勢構想，不要先產圖。
```

Skill 的名稱是 `line-sticker-maker`；GitHub repository 名稱是 `line-sticker-Q-maker-skill`。

## 必要輸入與選填資訊

必要輸入包括：

1. 主角參考圖片。
2. 貼圖主題。

可以額外提供：

- 指定詞句、用字、標點或語氣。
- 角色服裝、道具或配色偏好。
- 想要呈現的職業、生活情境或聊天用途。
- 希望避開的姿勢、元素或文字風格。

若有多位主角，必須說明要使用哪一位或是否要同時使用。指定詞句會保留原文，不會在未確認的情況下擅自改寫。

## 圖像與排版規格

### 角色風格

- 臉部寫實，身體卡通化，整體為 Q 版娃娃比例。
- 8 款貼圖使用同一位主角，保持臉部、髮型、服裝基調、光影、配色與筆觸一致。
- 依參考圖片保留可辨識的臉部特徵與個人特色。

### 總圖規格

- 橫向 16:9。
- 4 欄 × 2 列，共 8 款。
- 編號順序為上排左至右，再下排左至右。
- 16:9 指整張總圖的比例，不是每一張切圖的比例。

### 背景、白框與留白

- 使用均勻純淺灰背景，建議色碼為 `#E5E5E5`。
- 背景不加入場景、紋理、漸層或不必要的投影。
- 文字、人物及道具圖案外緣使用清楚連續的白色描邊。
- 每格四周保留約該格寬高 8% 的安全邊距。
- 人物、文字、道具與白框都不能跨格，也不能碰到預定切線。

## 工作流程與確認關卡

### 第一階段：提出 8 款文字

Skill 會根據主題提出 1 至 8 號文字，並附上簡短的姿勢或排版構想。文字應該自然、適合聊天且彼此有變化。

這個階段不會產生圖片。使用者必須明確確認 8 款文字後，才會進入下一階段。

### 第二階段：建立專案資料夾

文字確認後，以 `主題_YYYY-MM-DD` 建立資料夾。若同名資料夾已存在，會加上流水號避免覆寫。

資料夾會保存：

- `brief.md`：主題、參考圖片、8 款文字、風格、構想及確認狀態。
- `prompt_v01.txt`：實際使用的產圖提示詞。
- `sheet_v01.png`、`sheet_v02.png`：總圖版本。

### 第三階段：產生與修改總圖

生成一張包含 8 款貼圖的 16:9 總圖，並逐項檢查：

- 是否確實為 4 欄 × 2 列。
- 是否有 8 款貼圖且順序正確。
- 文字是否逐字符合已確認內容。
- 角色外貌與整組風格是否一致。
- 白框是否連續完整。
- 每格是否保留足夠的裁切安全空間。

若使用者要求修改，會保留原始版本並建立新版本，例如 `sheet_v02.png`。修改後必須重新確認最新版本，才能進入切割階段。

### 第四階段：切割與去背

只有已確認的總圖可以切割。初始切線依總圖實際寬高計算，再檢查切線是否落在空白區；如果切線會裁到人物、文字或白框，應先修正總圖，而不是直接切割。

切割後輸出：

```text
cropped/01.png 至 cropped/08.png
```

這 8 張仍保留淺灰背景。確認切割結果後，才逐張移除淺灰背景並輸出真正帶有 alpha 通道的透明 PNG：

```text
transparent/01.png 至 transparent/08.png
```

去背時只移除背景連通區，不應誤刪白框、眼白、衣服、道具或圖案中的白色與灰色細節。

### 第五階段：品質檢查與交付

交付前檢查：

- 8 張圖片都可以開啟。
- 圖片順序與 8 款文字正確對應。
- 沒有漏字、錯字、重複貼圖或裁到人物與白框。
- 透明 PNG 的背景區域確實為透明 alpha，而不是灰色或棋盤格畫面。
- 在深色和彩色底上檢查灰邊、背景殘留及前景誤刪。

通常會另外提供：

- `transparent_preview.png`：方便檢視的透明貼圖預覽。
- `主題_透明貼圖.zip`：包含 8 張透明 PNG 的 ZIP 封裝檔。

## 完整使用範例

以下示範從文字確認一路到素材交付的對話方式。

### 1. 使用者提出需求

```text
使用 $line-sticker-maker。
我上傳了一張人物照片，主題是「職場日常」。
請製作臉部寫實、身體卡通的 Q 版娃娃貼圖。
指定詞句：「收到！」、「辛苦了！」、「下班啦！」。
先給我 8 款文字和姿勢構想，不要先產圖。
```

### 2. Skill 提出文字

```text
1. 早安，開工啦！——拿著咖啡揮手
2. 收到！——精神抖擻地舉手敬禮
3. 馬上處理——坐在電腦前快速打字
4. 辛苦了！——微笑雙手遞上飲料
5. 開會中——抱著筆記本認真聆聽
6. 我確認一下——托腮查看筆記，旁邊有小問號
7. 拜託了！——雙手合十誠懇請託
8. 下班啦！——背起包包開心跳起來
```

接著等待使用者明確回覆「文字確認」或提出修改。沒有確認前，不建立本次專案資料夾，也不產圖。

### 3. 文字確認後產圖

使用者回覆：

```text
8 款文字確認，請開始產生總圖。
```

Skill 會建立例如 `職場日常_2026-09-13` 的資料夾，產生 16:9、4 欄 × 2 列總圖，展示 `sheet_v01.png`，並等待使用者確認或修改。

### 4. 確認圖片後切割去背

使用者回覆：

```text
sheet_v01.png 沒問題，請進行切割與去背。
```

Skill 才會輸出 8 張 `cropped/*.png`，再輸出 8 張 `transparent/*.png`，檢查 alpha 通道與白框，最後提供預覽圖及 ZIP 檔。

## 注意事項

- 本 Skill 產出的是貼圖素材，不會自動替使用者上架 LINE。
- 若要符合 LINE 當前上架規格，應在使用者提出需求後，另外查核官方最新的尺寸、容量與檔案規範。
- 修改文字時，先確認新的詞句，再重新產生圖片；不要在未確認的情況下改動已核准文字。
- 修改總圖後，必須重新確認最新版本，不能沿用舊版本的圖片確認狀態。
- 產圖工具無法使用時，應如實說明，不應把提示詞或預覽敘述當成已完成圖片。
